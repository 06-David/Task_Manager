## 1. 目标与隔离

依据 `./docs/需求规格说明书.md`，验证任务操作、状态变化、本地存储、弹窗与拖拽顺序。风险边界见 `./docs/风险分析.md`。

领域测试使用独立的内存存储替身，组件测试使用 jsdom；不读取真实用户数据。浏览器检查使用独立浏览器上下文。领域测试通过不等于界面验收通过，覆盖率不设硬门槛。

## 3. 关键用例

| 场景 | 输入或操作 | 预期 |
| --- | --- | --- |
| 生命周期 | 创建、编辑、完成、重新打开、删除并读取存储 | 标识保持，数据一致，删除后为空 |
| 零值顺序 | 编辑切换状态，目标 order 为 0 | 接受合法零值；状态不变时保持原顺序 |
| 写入失败 | 首次保存成功，再令写入抛异常 | 返回失败，内存输入和上次持久化内容不被破坏 |
| 读取失败 | 拒绝读取或 JSON 损坏 | 返回明确失败状态，不向上抛出异常 |
| 备份失败 | JSON 损坏且备份也不能写入 | 仍返回容错结果 |
| 版本与坏记录 | 高版本信封，或混合有效和无效任务 | 高版本读取不覆写；可处理集合中保留有效项 |
| 偏好隔离 | 保存主题与视图偏好 | 不改变任务存储内容 |
| 状态矩阵 | 三种状态的九种组合 | 不复制任务，不修改输入，完成时间正确 |
| 长度边界 | 描述去空白后 500 或 501 长度 | 500 通过，501 拒绝 |
| 特殊文本 | 标记、引号与符号往返存储 | 原文保留；不代表界面安全专项通过 |
| 栏内排序 | 上移、下移、原位、目标无效 | 顺序符合插入位置，其他任务相对顺序保留 |
| 排序元数据 | 拖动同列卡片 | 其他列与内容更新时间保持不变 |
| 弹窗开关 | 首次打开、创建后关闭、取消删除 | 不存在常驻遮罩，不误删任务 |
| 删除确认 | 确认删除后读取存储 | 任务被移除且对话框关闭 |

下溢边界按 ORDER_FLOOR 的减一、等值、加一测试。移动后不仅检查权重不重复，还检查实际顺序、具体权重和重排告警，避免测试通过但没有验证目标行为。

## 4. 执行方式

先按 `./README.md` 安装环境，再运行：

```sh
npm ci
npm run test:unit
npm run lint
npm run build
```

只执行某个回归文件：

```sh
npm run test:unit -- tests/unit/models/domainRegression.spec.js
```

既有测试中的非法数据归一化会输出预期告警，应结合测试结果判断，不将这些告警误认为测试失败。
