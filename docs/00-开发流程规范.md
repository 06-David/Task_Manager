## 开发方式

课堂目标是在约 20–25 分钟实践中完成核心演示，按“计划 → 实现 → 验证”推进。建议三轮为核心操作、看板主题、验收修复，不强制十个里程碑和逐项变更审批。

保留真实 Git 记录，不补造提交。新增需求先说明用途和范围影响，及时更新相关文档。旧代码中的 FR、EX 编号为历史引用，不再要求补齐原有扩展规划。

## 运行与验证

项目根目录执行 `npm ci`、`npm run dev`，访问 `http://127.0.0.1:8080/`。入口 index.html 需要 Vite 服务，不能通过 file 协议运行。

领域逻辑修改运行相关测试，交互修改必须补浏览器验证。交付前运行 `npm run test:unit`、`npm run lint`、`npm run build`，并记录真实结果。测试数量和覆盖率不能替代页面验证，不设覆盖率硬门槛。

修改弹窗等交互时，重点检查首次加载、打开、关闭、取消、确认及刷新；不只检查构建成功。

## 交付

源码、测试、五份文档、配置及依赖锁文件统一放在本项目。node_modules、dist 与本地工具资料不提交。克隆后无需开发者本机路径。验证结果以 `./docs/04-测试设计.md` 为准。
